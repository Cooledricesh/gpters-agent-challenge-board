# scripts/data — 커리큘럼·사례 매핑 데이터

## 파일

- `curriculum-23.json` — 23기 기술트리 커리큘럼(적용: `apply-curriculum.mjs`).
- `case-study-mapping.json` — 22기 사례글 → 과제 배치(적용: `import-case-studies.mjs`).
- `case-meta.json` — 사례글 메타(제목·요약·도구·태그·원문 URL). 옵시디언 원본에서 추출.

## 사례글 매핑 관례

2026-07 재검증(98건 원문 전수 대조)에서 확립한 기준. 재매핑 시 이 관례를 유지할 것.

1. **설명 기반 매핑**: 과제 "제목"이 아니라 description + detail의 **완료 기준**에
   사례 원문이 부합하는지로 판단한다. (예: '에이전트 기억 가꾸기'=내장 메모리 파일,
   '옵시디언에 연결하기'=외부 노트 볼트, '기억 보조장치'=Honcho/Mem0 외부 백엔드 — 혼동 금지.)
2. **기초 과제(설치·텔레그램 연결)는 그 과정이 글의 중심 서사일 때만 배치한다.**
   봇을 운영한 글 전부에 논리적으로는 성립하지만, 전부 배치하면 예시 목록이 폭발한다.
   운영 사실만으로 완료가 구조적으로 확실한 대형 운영기(예: 상시 운영 참모진 기록)는 예외적으로 허용.
3. **도구 정합성**: 오픈클로/헤르메스 반려 에이전트 없이 ChatGPT·Claude Code 단독·순수
   스크립트만으로 한 사례는 과제가 명시적으로 외부 도구를 허용하지 않는 한 배치하지 않거나
   low로 낮춘다(참고 사례 성격일 때만).
4. **confidence 기준**: high=완료 기준을 원문이 명백히 시연 / medium=취지 충족이나 세부
   증거 부족(부분 시연) / low=정황만 있거나 도구·기준 불일치가 있는 참고 사례.
   계획·시도만 한 것은 배치하지 않는다.
5. **rationale에는 원문 근거만 인용한다.** 원문에 없는 문구를 인용하지 말 것
   (과거 '두 번째 봇 제작까지 성공' 오인용 사례가 있었다).
